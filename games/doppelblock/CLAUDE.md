# 도펠블록

저장소 전체에 걸리는 규칙은 루트 `CLAUDE.md`에 있다. 여기에는 이 게임에만
해당하는 것만 적는다.

## 명령

```bash
node games/doppelblock/logic.test.js      # 규칙·완전 탐색 테스트
node games/doppelblock/solver.test.js     # 논리 기법·힌트 테스트
node games/doppelblock/generator.test.js  # 생성기·난이도 테스트

node games/doppelblock/bake.js 8 45 12345 >> /tmp/eight.txt  # 큰 판 미리 굽기
```

## 큰 판을 미리 굽는 이유

**판을 만든다.** 무작위로 뽑아 매겨 보고 버리는데, 8×8은 논리로 풀리는 판이
0.04%뿐이라 한 판에 18초가 든다. 게임 안에서 만들기에는 너무 무거워서 미리
구워 둔다.

씨앗을 달리해 코어 수만큼 동시에 돌리고 결과를 합치므로, **합칠 때 중복을 다시
걸러낸다** — 프로세스 안에서만 중복을 보기 때문이다.

## 힌트

넣은 값이 정답과 다르거나 연필 표시가 정답 값을 지워 두었으면 그 칸을 짚고 멈춘다. 없으면
`solver.nextHint`가 **넣은 값과 연필 표시에서 기법을 쉬운 순서로 보고 처음 새로 알게 된 것
하나**를 돌려준다. 칸이 확정되면 값을 넣고, 후보만 줄면 연필로 남긴다. 예전에는 연필 표시를
"이미 아는 단계인가"를 가리는 데만 쓰고 추론에는 넣지 않았다 — 틀린 표시를 근거로 삼을까
봐서였는데, 이제 틀린 표시를 먼저 짚으므로 사람이 좁혀 둔 것에서 이어 간다. **연필 후보가
하나만 남은 칸이 있으면 그 값을 넣는 것을 먼저 짚는다.** 화면은 좁혀진 후보를 이미 적어 둔
표시와 겹쳐 적어 이런 칸이 생기는데, 이것이 없으면 판이 다 정해졌는데도 힌트가 "찾지
못했다"에 멈췄다.

**배치 좁히기는 따질 경우가 적은 줄에만 쓴다**(`solver.js`의 `MAX_CASES`, 여덟 가지). 경우는
검은 칸 두 자리와 그 사이 숫자 묶음으로 센다 — 숫자 순서까지 다른 배치로 세면 8×8 한 줄이
천 가지를 넘지만, 사람은 그렇게 따지지 않는다. 좁혀지는 줄이 여럿이면 경우가 가장 적은 줄을
고른다. 처음 걸린 줄을 쓰던 때는 8×8에서 배치 천 가지를 따져야 하는 줄이 힌트로 나왔다.
상한을 넘는 줄로만 풀리는 판은 논리로 안 풀리는 판으로 쳐서 버린다 — 구워 둔 8×8 149판 중
4판이 여기에 걸려 목록에서 뺐고, 7×7은 모두 남았다.
