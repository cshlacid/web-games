# 라이트 업

저장소 전체에 걸리는 규칙은 루트 `CLAUDE.md`에 있다. 여기에는 이 게임에만
해당하는 것만 적는다.

닛코리의 Akari(美術館)다. 흰 칸에 전구를 놓아 모든 흰 칸을 밝히되, 전구끼리 서로 비추지
않고, 벽의 숫자는 맞닿은 전구 수다. 폴더와 식별자는 영어 이름을 따라 `lightup`이다.

## 명령

```bash
node games/lightup/rules.test.js      # 빛이 닿는 칸, 서로 비추는 전구, 숫자 판정
node games/lightup/solver.test.js     # 규칙별 추론, 풀었다고 한 판의 답이 하나인지, 힌트
node games/lightup/generator.test.js  # 구워 둔 판 180장을 다시 푼다

node games/lightup/bake.js > games/lightup/puzzles.js   # 다시 굽기(10초쯤)
```

## 판은 미리 굽는다

쉬움 7×7, 보통 10×10, 어려움 10×10을 예순 판씩 `puzzles.js`에 둔다. 굽는 데 10초면 끝나
실시간으로 만들 수도 있지만, 슬리더링크·누리카베와 같은 틀(굽기 → 고르기)을 따랐다.

**정답 전구부터 놓고 숫자를 지운다.** 벽을 점대칭으로 흩고, 어두운 칸 하나에 전구를
놓기를 판이 다 밝을 때까지 되풀이한다(어두운 칸은 어느 전구에게도 보이지 않으니 서로
비추는 전구가 생기지 않는다). 모든 벽에 숫자를 적고, 숫자를 하나씩 지워 보며 풀이기가
여전히 끝까지 풀면 지운 채로 둔다.

**숫자를 다 둬도 안 풀리는 판이 대부분이다**(7×7 스무 판 중 열여덟). 벽 없는 넓은 빈
곳에서 전구 자리가 여럿 나온다. 그래서 풀이기가 막힌 칸을 (점대칭 짝과 함께) 숫자 벽으로
바꿔 빈 곳을 나눈다. 정답 전구가 아니고, 벽이 되어도 정답 전구만으로 판이 다 밝은 칸만
바꾼다.

**답의 수를 따로 세지 않는다.** 풀이기는 참인 것만 이끌어 내므로 끝까지 풀리면 답이
하나다. `solver.test.js`가 풀었다고 한 판의 해를 끝까지 세어 확인한다.

**난이도.** 쉬움과 보통은 규칙(숫자 벽, 빛 받은 칸, 밝힐 자리가 하나뿐인 칸)만으로 풀리는
판이다. 어려움은 "여기에 전구를 두면 모순"이라는 가정을 한 겹 허락하고, 가정이 한 번은
드는 판만 쓴다. **가정은 두 걸음 안에 막히는 것만 허락한다**(`solver.js`의 `SHORT_TRIAL`).
그보다 길게 따라가야 막히는 판은 경우의 수를 다 따져 봐야 하는 판이라 굽지 않는다.

## 힌트

어긋난 칸(정답이 아닌 전구, 정답 전구 위의 점)이 있으면 그 번에는 걷어 내기만 하고, 없으면
`solver.next`로 **지금 판에서 한 걸음에 알아낼 수 있는 칸**을 채운다. 가정은 가장 빨리 막히는
칸을 고른다 — 처음 걸린 칸을 주면 한참 따라가야 막히는 것이 나온다. 규칙을 숫자 벽 → 빛 받은 칸 → 밝힐 자리가 하나뿐인 칸 →
가정 순서로 보므로 쉬운 까닭이 먼저 나온다. 까닭은 `why.code`로 돌려주고 화면이
`lightup.why.*`로 엮는다.

## 화면

**점(전구 아님)은 판정에 쓰지 않는다.** 판을 다 밝히고 숫자가 맞으면 끝난다.

**끌어서 놓을 수 있는 것은 점과 지우개뿐이다.** 전구를 끌어 놓게 두면 손가락이 지나간
줄이 통째로 서로 비추는 전구가 된다(Queens의 왕관과 같은 까닭). 판에 `touch-action:
none`을 걸었으므로 그 안에는 click으로 도는 조작이 없다.

SVG 좌표에서 칸 한 변은 100이다 — 슬리더링크에서 칸을 1로 두었다가 웹킷이 숫자를
가운데서 비껴 그렸다.
