# 노노그램

저장소 전체에 걸리는 규칙은 루트 `CLAUDE.md`에 있다. 여기에는 이 게임에만
해당하는 것만 적는다.

가장자리 숫자대로 칸을 칠해 그림을 찾는 논리 퍼즐(피크로스·노노그램)이다. 폴더와
식별자는 `nonogram`으로 두고 사람이 읽는 이름만 한글로 붙였다.

## 명령

```bash
node games/nonogram/rules.test.js      # 힌트 뽑기·완성 판정
node games/nonogram/solver.test.js     # 줄 좁히기·논리 풀이·힌트
node games/nonogram/generator.test.js  # 그림 검사와 판 만들기
```

## 다 풀렸는지는 정답과 대 보지 않는다

`isDone`은 모든 줄이 **힌트대로 채워졌는가**만 본다. 정답과 한 칸씩 견주면 "정답을
따라 그리는" 놀이가 되지만, 힌트로 가리면 "규칙을 만족시키는" 놀이가 된다. 답이
하나뿐인 판만 내보내므로 두 판정은 결국 같은 곳에 닿는다.

**아님 표시(가위표)는 판정에 끼어들지 않는다.** 사람이 쓰는 메모일 뿐이라, 다 칠하고
가위표를 하나도 안 쳤어도 끝난다.

## 풀이기는 사람의 수순을 그대로 쓴다

한 줄만 보고 **어느 배치에서나 칠해지는 칸**과 **어느 배치에서나 비는 칸**을 가려낸다
(`narrow`). 사람이 이 퍼즐을 푸는 방식이 정확히 이것이라, 같은 코드가 "찍지 않고
논리로 풀리는가"의 판정도 된다.

배치를 다 만들어 두지 않고 훑으면서 표시만 모은다. 열다섯 칸에 힌트가 다섯이어도
한순간에 끝난다.

**여기를 통과한 판은 답도 하나뿐이다.** 줄 좁히기는 모든 답에 공통인 칸만 채우므로,
전부 채워졌다면 답이 갈릴 자리가 없었다는 뜻이다 — 그래서 답을 따로 세지 않는다.

## 작은 판은 그림, 큰 판은 무작위

다 풀면 무엇이 나오는지가 이 놀이의 보상이라, 5칸과 10칸은 **손으로 그린 그림**을
쓴다(`pictures.js`, 스물두 장). 15칸은 그 크기에서 손으로 그릴 만한 그림의 품이 커서
무작위로 만든다 — 큰 판은 푸는 맛 자체가 목적이다.

**그림도 무작위 판도 논리로만 풀리는지 검사해서 내보낸다.** 새 그림을 더하면
`generator.test.js`가 크기와 풀림을 함께 본다(처음 그린 닻이 여기서 걸려 다시
그렸다).

**무작위 판은 이웃을 보고 다수 쪽으로 맞추기를 두 번 돌린다**(`smooth`). 이것이
없으면 소금 뿌린 듯 흩어져 힌트가 `1 1 2 1 1`처럼 길어지는데, 힌트가 길면 판 옆자리를
잡아먹어 칸이 작아지고 무엇보다 그림처럼 보이지 않는다. 열다섯 칸 판의 힌트가 한
줄에 평균 넷에서 둘로 줄었고, 칸도 18px에서 20px이 됐다.

## 화면

**칸 크기는 힌트 길이까지 넣어 판마다 다시 잰다**(`measure`). 힌트 한 칸은 판 한 칸의
0.66배다 — 같은 폭으로 두면 힌트 자리가 판보다 넓어진다. 칸은 정수 픽셀로 끊어 칸마다
폭이 갈리지 않게 한다.

**끌어서 칠한다.** 판에 `touch-action: none`을 걸었으므로 이 자리에는 click으로 도는
조작을 두지 않고 포인터 이벤트로만 짠다(저장소 전체 규칙). 처음 벗어난 방향으로
**축을 잠근다** — 잠그지 않으면 손이 흔들릴 때 옆줄까지 칠해진다.

**시작한 칸이 이미 그 값이면 지우는 손질이 된다.** 칠한 것을 지우려고 모드를 바꾸지
않아도 되고, 이 하나로 칠하기·지우기가 한 손가락에 들어온다.

**다 맞춘 줄은 힌트 숫자를 흐린다.** 남은 줄만 눈에 들어오게 하려는 것이고, 이
게임에서 "어디까지 했나"의 절반은 이 표시로 읽힌다.

**결과는 판 위에 덮지 않고 아래에 편다.** 루트 규칙의 예외다 — 다 푼 그림을 보는 것이
이 놀이의 보상인데 덮개가 그것을 가린다. 같은 이유로 판이 끝나면 **가위표를 감춰**
그림만 남긴다.
